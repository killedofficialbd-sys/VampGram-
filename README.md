# Vampgram 6.0 — BLOODLINE

**Your Private Digital World** — расширенная PWA-сборка Vampgram на Firebase Authentication и Cloud Firestore. Проект по-прежнему работает без Node.js, React, Vite и обязательной сборки: разместите файлы в корне сайта.

## Что нового в 6.0

### Социальная лента
- Публичная лента публикаций авторизованных пользователей.
- Текстовые записи, фотографии и короткие видео.
- Автоматическая оптимизация изображений перед отправкой.
- Лайки, комментарии, сохранение публикаций.
- Редактирование/удаление своих публикаций.
- Жалобы на публикации.
- Медиа хранится частями в Firestore; Firebase Storage и `storage.rules` не добавлялись.

### Communities
- Создание тематических сообществ.
- Просмотр каталога, вступление в сообщество и выход из сообщества (кроме владельца).
- Внутренние текстовые публикации участников.
- Выход из сообщества (создатель остаётся владельцем).

### Профили и уведомления
- Поле статуса профиля.
- Уведомления внутри приложения о лайках и комментариях.
- Отметка уведомлений прочитанными.
- Сохранённые публикации пользователя.

### Инструменты и данные
- Резервный экспорт профиля, собственных публикаций и последних сообщений в JSON.
- Диагностика текущего сеанса, профиля Firestore, ленты и сообществ.
- Поиск по последним 300 сообщениям в загруженных диалогах (до 25 диалогов за поиск).
- Founder Console показывает статистику выборок публикаций и сообществ; журнал действий увеличен до 50 последних записей.

### Сохранённые функции предыдущих версий
- Личные и групповые диалоги, истории, каналы.
- Ответы, реакции, редактирование/удаление собственных сообщений.
- Постраничная загрузка более старых сообщений сверх последних 300.
- Голосовые сообщения, файлы, фото и видео.
- Личные аудио/видеозвонки WebRTC.
- Founder badge для подтверждённого аккаунта основателя.
- Тёмное оформление, адаптация под мобильные устройства, PWA.

## Установка и обновление

1. Сначала сделайте копию старой папки проекта и экспортируйте важные данные Firestore.
2. Распакуйте файлы архива и замените файлы проекта. Не удаляйте существующую базу Firestore и документы.
3. Откройте Firebase Console → проект **`vampgram-2dbdd`** → Firestore Database → Rules.
4. Опубликуйте `firestore.rules` из этой версии.
5. В Firestore Database → Indexes добавьте индексы из `firestore.indexes.json` (если Firebase не создал их автоматически).
6. Оставьте включённым Firebase Authentication → Email/Password.
7. Откройте сайт по HTTPS или localhost. Закройте PWA/вкладки и откройте Vampgram заново, чтобы загрузился Service Worker `vampgram-shell-v6-0-0`.

**Важно:** новые разделы используют новые коллекции (`feedPosts`, `communities`, `notifications`) и вложенные коллекции сохранённых публикаций. Старые `conversations`, `messages`, `stories`, `channels`, `users` и `media` не мигрируются и не удаляются. При публикации правил проверьте Firebase Console на тестовой копии проекта перед основной базой.

## Ограничения текущей сборки

Это клиентская PWA без доверенного серверного кода. Поэтому следующие функции не объявляются готовыми:

- **Фоновые push-уведомления:** в 6.0 есть уведомления внутри приложения. Для FCM в фоне нужны VAPID key, Firebase Messaging и согласованный Service Worker.
- **Групповые звонки:** текущие звонки остаются 1:1. Для стабильных групповых аудио/видеокомнат нужен SFU-сервер (например, отдельная инфраструктура LiveKit/mediasoup) и TURN.
- **Полное E2EE чатов:** WebRTC использует DTLS-SRTP для транспорта звонка, но текстовые чаты не имеют сквозного шифрования с обменом и проверкой ключей.
- **Полное администрирование Firebase Auth:** блокировка в Founder Console ограничивает доступ внутри Vampgram, но не удаляет аккаунт из Firebase Authentication. Для этого нужны Cloud Functions/Admin SDK.
- **Роли администраторов сообществ и сложная модерация:** в этом клиентском релизе доступны создание, вступление, публикации и выход; выдача доверенных ролей должна выполняться сервером.
- **Поиск:** текущий поиск сообщений ограничен последними 300 сообщениями каждого из максимум 25 загруженных диалогов, а не полным архивом.
- **Экспорт:** JSON backup включает до 30 последних диалогов (до 300 сообщений каждого) и до 100 собственных публикаций. Это экспорт, а не автоматическое резервное копирование Firebase.
- **Лимит медиа социальной ленты:** до 4 МБ на фото/видео после оптимизации. Большие видео требуют объектного хранилища.

## Проверка после установки

Рекомендуемый тестовый порядок на двух аккаунтах:

1. Войти в оба аккаунта и убедиться, что старые личные и групповые чаты сохранились.
2. Создать публикацию без файла, затем публикацию с небольшим изображением.
3. Со второго аккаунта поставить лайк и оставить комментарий; на первом проверить уведомления.
4. Сохранить публикацию и проверить раздел «Сохранённое».
5. Создать сообщество, вступить в него со второго аккаунта и разместить запись.
6. Сделать JSON-экспорт и открыть файл на устройстве.
7. Запустить «Диагностику» из меню.
8. Только после успешных тестов обновить основную базу.

## Без Firebase Storage

Проект использует Cloud Firestore для профилей, публикаций, историй, вложений и чанков файлов. Отдельный `storage.rules` не нужен и не добавлялся. Для больших медиа-файлов Firestore не рекомендуется — в следующей серверной архитектуре лучше подключить объектное хранилище.
