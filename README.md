# Vampgram 5.0 — Maximum / Hybrid

Обновлённая PWA-сборка существующего Vampgram на Firebase Authentication и Cloud Firestore. Файлы размещаются в корне проекта; отдельная сборка Node.js/Vite не нужна.

## Что вошло в 5.0

### Чаты и сообщения
- Личные и групповые диалоги (до 50 участников, включая создателя).
- Сохранение сообщений и обновление карточки диалога одной атомарной Firestore batch-операцией.
- Исправленная логика статусов: одна галочка — отправлено; две — когда все остальные участники диалога отметили чтение после времени сообщения.
- Счётчик непрочитанного не сбрасывается только от открытия переписки: отметка прочтения выполняется, когда пользователь находится внизу истории и вкладка видима.
- Ответы/цитирование, реакции, редактирование и удаление собственного текстового сообщения.
- Индикатор набора текста, поиск пользователя по `@username` или точной почте, обновление снимков профиля.
- Экспорт последних 300 сообщений открытого диалога в TXT.

### Социальные функции
- Истории с автоматическим сроком действия 24 часа, просмотром и счётчиком просмотров для автора.
- Публичные каналы: создание, подписка и текстовые публикации.
- Жалобы на пользователя и базовая модерация в Founder Console.

### Founder
- В качестве единственного заранее заданного адреса основателя используется `killedofficialbd@gmail.com`.
- Доступ требует одновременно совпадения email и подтверждённого `email_verified` в Firebase ID token. Одна лишь регистрация с таким адресом или локальное изменение профиля права не дают.
- После подтверждения адреса поле `users/{uid}.isFounder` создаётся/обновляется приложением. Другим авторизованным пользователям доступна публичная отметка FOUNDER в результатах поиска, профиле, заголовке личного чата и авторских сообщениях.
- Founder Console включает выборку профилей (до 60), диалогов (до 100), жалоб (до 40), историй (до 60), последние записи журнала (до 20), закрытие жалоб и внутреннее ограничение/восстановление аккаунта в Vampgram.
- Доступ к административным операциям дополнительно защищён правилами Firestore, а не только скрытием кнопки в интерфейсе.

### Интерфейс, PWA и уведомления
- Обновлённая гибридная тема: почти чёрная основа, бордовые/кроваво-красные акценты, стеклянные панели и готические заголовки.
- Настройки оформления и уведомлений на текущем устройстве.
- Уведомления в активной вкладке/браузере при разрешении Notification API.
- Обновлён Service Worker до `vampgram-shell-v5` и manifest для принудительного обновления PWA.

## Настройка Firebase

1. Оставьте исходный Firebase project/config из `index.html`, если он соответствует вашей базе. Не создавайте новый проект только ради этой сборки.
2. В Firebase Console включите Authentication → Sign-in method → Email/Password.
3. В Firestore Database → Rules замените правила содержимым `firestore.rules` из этого архива и нажмите **Publish**.
4. При использовании Firebase CLI можно выполнить:

   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```

5. Если сайт размещён на GitHub Pages, загрузите все файлы прямо в корень репозитория и выполните commit/push. Не используйте `firebase deploy --only hosting`, пока хостинг остаётся GitHub Pages.
6. Обновите страницу, закройте установленную PWA и откройте заново. При сохранении старого интерфейса очистите данные сайта/кэш Service Worker.

## Активация Founder для `killedofficialbd@gmail.com`

1. В Firebase Authentication должен существовать аккаунт с точным адресом `killedofficialbd@gmail.com`.
2. Войдите именно в этот аккаунт в Vampgram.
3. Откройте Настройки → блок Founder → нажмите «Отправить письмо».
4. Перейдите по ссылке подтверждения из Firebase-письма.
5. Вернитесь в приложение и снова откройте Настройки → Founder → «Обновить статус».
6. После обновления токена и синхронизации профиля появится Founder-бейдж и кнопка Founder Console. Остальные пользователи увидят отметку в поиске, профиле и чате.

Сам архив не создаёт Firebase Auth-аккаунт, не знает пароль и не может подтвердить почтовый адрес за владельца. Если почта ещё не зарегистрирована, сначала создайте этот аккаунт обычной процедурой Firebase Authentication.

## Что осталось за пределами статической сборки

Эти функции нельзя безопасно реализовать только клиентским HTML без дополнительных доверенных сервисов или внешней инфраструктуры:

- Фоновые push-уведомления через FCM требуют настройки Firebase Cloud Messaging и Service Worker push handler.
- Групповые аудио/видеозвонки не реализованы; текущие WebRTC-звонки остаются личными. Для стабильных соединений за сложным NAT может потребоваться TURN.
- Полное отключение/удаление пользователя в Firebase Authentication, рассылки всем пользователям, серверная выдача ролей и гарантированный аудит требуют Cloud Functions или отдельного доверенного сервера. Текущая блокировка `accountStatus` ограничивает работу внутри Vampgram, но не удаляет пользователя из Firebase Auth.
- Полноценное E2EE для сообщений с проверкой ключей не добавлено. WebRTC медиа использует DTLS-SRTP транспорт, что не равнозначно E2EE чата.
- Истории хранят небольшие сжатые изображения в Firestore; обычные вложения используют существующий механизм чанков Firestore. Firebase Storage и `storage.rules` не добавлялись.
- Founder Console показывает ограниченные последние выборки, а не бесконечную постраничную аналитику.

## Проверки и ограничения тестирования

JavaScript-модуль и статические ресурсы проверяются перед упаковкой. Реальный обмен между двумя аккаунтами, фактическая доставка почты, правила в опубликованной Firebase-базе, камера/микрофон на устройстве и сетевые условия WebRTC требуют запуска в вашем Firebase-проекте и не могут быть подтверждены локальной проверкой архива.

## Важно

Перед заменой файлов сделайте резервную копию текущего репозитория и Firestore. Новые правила ограничивают доступ к новым коллекциям и операциям. Проверьте их на тестовом проекте Firebase перед публикацией в основной базе.

## Vampgram 5.0.1 — hotfix после мобильного тестирования

Эта сборка содержит исправления по результатам проверки на Android:

- мобильная авторизация принудительно переходит в одну колонку, без уменьшенной двухколоночной карточки;
- боковая панель и экран переписки занимают всю ширину телефона; верхние действия прокручиваются внутри панели и не растягивают страницу;
- элементы ввода, вложения, модальные окна, админ-списки и кнопки ограничены шириной контейнера;
- добавлена отдельная кнопка Founder Console в верхней панели для подтверждённого аккаунта основателя;
- список чатов дополнительно восстанавливает старые записи, если предыдущие версии сохраняли список участников в `participants`, `userIds` или `memberIds`;
- истории поддерживают фото и видео MP4/WebM/MOV до 4 МБ; медиа хранится в чанках Firestore, Firebase Storage не используется;
- правила Firestore дополнены для медиа историй и совместимости с ранними схемами диалогов;
- Service Worker обновлён, чтобы устройства не оставались на старом интерфейсе.

### Обязательное обновление Firestore Rules

После замены файлов открой Firebase Console → Firestore Database → Rules и опубликуй `firestore.rules` из этого архива. Без публикации новых правил операции с историями, каналами, группами и новыми медиа могут завершаться `Missing or insufficient permissions`.

Не публикуй правила из старого архива поверх этой версии. `storage.rules` не требуется.

### После установки на Android

1. Обнови файлы сайта.
2. Опубликуй `firestore.rules`.
3. Закрой установленный Vampgram и вкладки сайта.
4. Открой сайт заново, дождись загрузки и перезапусти приложение.
5. Если браузер продолжает показывать старую разметку, очисти данные сайта/кэш именно для локального адреса и открой его снова.

### Примечания по видеоисториям

Видео хранится в Firestore частями. Для устойчивой работы ограничен размер одного видео 4 МБ. Для более крупных файлов понадобится Firebase Storage либо серверное объектное хранилище; в этой сборке Firebase Storage не подключён.


## Vampgram 5.0.2 repair notes

- Fixed `activeUser()` so older user documents without `accountStatus` are treated as active; only explicit `suspended` blocks access.
- Conversation membership checks now recognize `members`, `participants`, `userIds`, and `memberIds`.
- Legacy conversation queries are merged even when modern-format chats exist.
- Story upload errors now log the Firebase operation context and show the Firebase error code.

Deploy the included `firestore.rules` to the same Firebase project (`vampgram-2dbdd`). Do not delete existing Firestore documents.
